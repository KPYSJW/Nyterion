후속 작업 2 — 장비 교체와 신규 지급의 소유권·저장 시점 정리
적용일: 2026-10-16

대상: 코드 리뷰 R04, R05

변경 내용
- 인벤토리 우클릭 장착, 장착 칸으로 드롭, 보관 칸으로 드롭, 장비 우클릭 해제를
  EquipmentDataManager의 TryEquipFromInventory / TryUnequipToInventory로 통일했다.
- 원래 보관 슬롯과 장착 슬롯을 기존 인스턴스 그대로 교환한다.
  같은 원본 ID를 가진 다른 인스턴스를 제거하거나 장비를 새로 복제하지 않는다.
- 두 데이터 상태를 확정한 뒤 장비 변경과 인벤토리 변경 알림을 각각 한 번 발생시킨다.
  이동 실패 시에는 데이터 변경, 알림, 저장 요청이 없다.
- 장비 교체 완료 시 ForceSaveGame을 한 번 요청한다. 직전 저장으로 인한 1초 쿨다운은
  건너뛰되 기존 로드 중·저장 차단·초기화 보호 조건은 유지한다.
- 보관함이 가득 차도 기존 보관 슬롯을 이용한 교체는 가능하다.
  빈 슬롯이 없는 단순 해제, 분해 예약 슬롯, 잘못된 인덱스, 오래된 선택은 거부한다.
- 드롭 이벤트가 처리되지 않은 경우의 보조 경로도 같은 데이터 작업을 사용한다.
  장비의 SetItem/ClearSlot은 표시 갱신만 담당한다.
  Shift를 누르고 장착 칸 밖에 놓아 UI만 지우는 경로는 차단했다.
- AddItem의 신규 장비 지급은 요청 수량 전체가 들어갈 때만 성공한다.
  공간이 부족하면 복제하지 않으며, 생성 후 수용 실패 시 미보관 복제본을 해제한다.
  실패 시 알림·저장을 요청하지 않는다. 등급이 결정된 인스턴스는 기존
  AddEquipmentInstance API를 사용한다.
- 저장 데이터 형식과 기존 에셋·씬 직렬화 필드는 바꾸지 않았다.

검증 결과
- Unity 2022.3.62f2 에디터에서 Assembly-CSharp / Assembly-CSharp-Editor 컴파일 성공.
- 기존 InventoryEquipmentSwapVerification을 확장하고 실행했다.
  1. 앞쪽 빈 슬롯 유무와 무관하게 원래 클릭 슬롯으로 기존 장비 반환.
  2. 가득 찬 보관함에서 교체, 같은 원본 ID의 다른 인스턴스 보존.
  3. 빈 장착 칸에 장착, 양방향 드롭, 양방향 보조 경로.
  4. 각 데이터 변경 알림 시점에 이미 두 슬롯의 최종 상태가 확정됨.
  5. 가득 찬 상태 해제, 분해 예약, 잘못된 인덱스, 오래된 선택의 실패 상태 보존.
  6. 반복 지급 실패와 0/음수·일부 수용만 가능한 요청에서 복제본·알림 증가 없음.
  7. 신규 장비 두 개 전체 지급 시 고유 인스턴스 ID와 알림 한 번.
  8. 격리 JSON 파일 저장·재읽기 후 새 매니저에 LoadFromSaveData 적용.
     슬롯 위치, 원본 ID, 인스턴스 ID, 등급, 수량 동일.
  9. 장착 UI 초기 주입·반복 활성화·비활성 중 변경 후 재활성 동기화.
- 결과: output/inventory-equipment-swap/verification.txt
- 스냅샷: output/inventory-equipment-swap/snapshot-*.json
- git diff --check 통과.

검증 범위와 수동 확인
- 자동 검증은 Editor의 격리된 PreviewScene과 별도 JSON 파일을 사용했다.
  실제 사용자 세이브 파일과 현재 열린 씬은 저장하거나 교체하지 않았다.
- 실제 플레이 중 SaveLoadManager의 자동 수집·파일 쓰기 및 프로세스 재시작은
  이번 자동 검증에 포함하지 않았다.
- Title → GameScene에서 A 착용 후 B를 드래그/우클릭으로 교체하고, 해제·역방향
  드롭도 확인한다. 교체 직후 다시 실행해 A/B가 각각 한 개이고 등급이 유지되는지 확인한다.
- 전체 인벤토리 상태·이벤트·표시 책임 중복(R03/R11)은 다음 후속 작업 3 범위다.
